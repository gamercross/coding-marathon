# 개인 개발 워크플로우 (dev-workflow)

이 저장소(`my-dev-process`)의 `docs/` 구조를 대신 다뤄주는 스킬입니다.
"문제 저장 → 문제 분석 → 패턴 분석 → 패턴 구현 → 구현 → 서비스 → 유지보수"의
7단계 중, AI가 대신 실행할 수 있는 세 지점(1단계 저장, 3단계 패턴 검색, 7단계
카탈로그 반영)을 명령 1·2·3으로 제공합니다. 명령 4는 이 7단계 밖에서, 외부
스킬/MCP를 들여올 때 우리 틀과 충돌하지 않는지 분석하는 별도 절차입니다.

**이 파일은 트리거·개요만 담습니다. 실제 실행 절차는 여기 없습니다** —
명령을 실제로 수행하는 시점에만 [`PROCEDURE.md`](PROCEDURE.md)를 읽으세요
(왜 이렇게 나눴는지는 저장소 루트 [`CLAUDE.md`](../../../CLAUDE.md) 참고).

## 언제 트리거되는가

| 사용자 요청 | 실행할 것 |
|---|---|
| "새 문제 시작", "이 프로젝트 저장해줘" | PROCEDURE.md 명령 1 |
| "비슷한 패턴 있어?" | PROCEDURE.md 명령 2 |
| "회고 작성", "이번에 배운 거 반영해줘" | PROCEDURE.md 명령 3 |
| "이 스킬 써볼까", "이 MCP 붙여줘", "이 플러그인 통합해줘" | PROCEDURE.md 명령 4 |

자연어 트리거가 실제로 이 SKILL.md를 불러오는지는 세션마다 다시 확인이
필요하다 — 확인이 안 되면 사용자에게 수동으로 `dev-workflow` 스킬을
지정해달라고 요청한다.

## 트랙 자동 인식 (ADR-0001의 Supportability 제약 반영)

`docs/01-problem-save/` 안에서 **`README.md`와 `prd-template.md`를 제외한 모든
`*.md` 파일**이 하나의 "트랙 템플릿"입니다. 새 트랙을 추가하고 싶으면 이
폴더에 파일 하나만 추가하면 되고, **이 스킬의 로직·문구를 바꿀 필요가
없습니다** — 항상 그 순간의 폴더 내용을 다시 나열하세요.

## 이 스킬이 하지 않는 것 (ADR-0001 Consequences 참고)

- 자체적으로 자동 테스트를 돌리지 않는다 — 검증은
  [`.claude/agents/verify.md`](../../agents/verify.md) 서브에이전트에 위임한다.
- Claude Code 밖에서는 동작하지 않는다 — 다른 환경에서는 `docs/`를 사람이
  직접 읽고 쓴다.

## 실전 검증 이력

`main` 브랜치 [worklog.md](../../../docs/00-overview/worklog.md)에 날짜순으로
기록됨 — 요약: 알고리즘 5건 + 프로젝트 2건 + 학습 1건, 총 8개 항목이 명령
1·2·3 절차 그대로 1→7단계를 완주.
